3. 기능과 시험

기획서의 기능 10가지와 시험 231개입니다.

기능내용
데이터 올리기발주실적·확정단가·품의서 표를 머리글로 알아보고 발주월·단가 표기를 맞춥니다. 틀린 줄은 버리지 않고 입력 경고로 알립니다.
절감액 계산품번마다 기준 단가를 찾아 절감·인상·변동 없음을 가르고, 기준 단가 출처와 「계산」 표시를 붙입니다.

품의 정보 입력·연결화면에서 기준단가·Lever·품의번호를 넣거나, 기호만 다른 품번의 품의를 버튼 하나로 연결합니다.
집계·그래프월별 절감·인상 막대, Lever·업체별 양방향 막대와 표, 규칙 기반 요약 문장을 보여 줍니다.
엑셀 보고서요약·월별·Lever별·업체별·품번별·발주상세·확인필요·품의서정보·입력경고 시트를 만듭니다.

6. 한계와 남은 일

  • 신규 품번의 품의서 자동 검색은 하지 않습니다 — 품의서 정보는 표로 올리거나 화면에서 입력합니다.
  • 사내 구매 시스템 자동 연동은 하지 않습니다(내려받은 엑셀을 올림).
  • 화면에서 입력한 품의 정보는 창을 닫으면 사라집니다 — 보고서 「품의서정보」 시트를 다음 달에 다시 올립니다.
  • (v1.1) 엑셀의 첫 행 고정과 수작업 입력 칸 색 구분은 넣지 못했습니다 — 동봉한 무료 SheetJS 가 셀 서식·틀 고정을 쓰지 않습니다. 필터는 들어 있고, 비고 열로 거르면 입력할 행이 모입니다.
  • (v1.1) 엑셀에서 예산단가를 직접 넣으면 상세 행은 수식으로 계산되지만 「집계 및 검증」 시트의 숫자는 만든 시점의 값입니다. 도구에서 입력하고 다시 내보내면 맞습니다.
  • (v1.1) 같은 협력사 코드·자재품번이 담당자·예산 단가 표에 다른 값으로 두 번 있으면 먼저 나온 값을 쓰고 경고합니다(기획안대로 중복 자체는 오류로 보지 않습니다).
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
