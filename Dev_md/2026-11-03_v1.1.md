# 2026-11-03 v1.1 — 상세 기획안 방식(발주 실적 × 담당자 × 예산 단가)

## 왜
첫 판(v1.0, 연초 단가표·품의서 흐름) 배포 뒤 기획자가 패들릿에 상세 기획안을 다시 올렸다(게시물 4129353795 「좀 더 상세하게 작성했습니다」, 원문은 CLAUDE.md 부록 B).
실제 보고 방식은 v1.0 과 다르다 — 발주유형 ZNB 발주를 협력사 코드로 담당자와, 자재품번으로 예산단가·NOTE 와 맞추고, 품목범주로 구매단가를 정해 차이금액·Impact·실적을 낸다.
v1.0 은 손대지 않고 새 화면 `budget.html` + 엔진 `js/budget.js` 로 흐름을 하나 더 두었다. 첫 화면 위에 안내 상자와 「예제로 바로 보기」를 붙였다.

## 한 일
- 엔진 `js/budget.js`(UMD, engine.js 와 별개)
  - 열 짝짓기 `mapColumns`(항목별 별칭 표 `ALIASES`, 한 머리글은 한 항목에만) · 표 판별 `detectKind`(담당자 → 협력업체 담당자, 예산단가 → 예산 단가, 품번+수량 → 발주 실적) · `readRows`.
  - 정규화: 협력사 코드 `codeKey`(공백·전각·대소문자만, **선행 0 유지**), 자재품번 `partKey`(공백만), 통화 `curKey`, 발주유형 `isZnb`.
  - `run`: ZNB 거르기 → 담당자 매칭(미매칭은 `ownerUnmatched` 로 빼고 오류 내역) → 구매단가 결정 `decidePrice`(0 자재비 · 3 조립비) → 예산단가(파일 > 화면 입력) → 수량·환율 검사 → 차이금액·실적·Impact(정수 반올림, 0.5 는 0 에서 먼 쪽) → 비고 다섯 가지(`NOTES`, 순서 고정, 「 / 」로 이음).
  - 환율 `DEFAULT_FX`·`normFx`·`fxFor`(글자 구성만 같은 JPY ↔ JYP 는 `similar` 로 바꾸지 않음).
  - 집계 `summarize`(기획안 8절·9절 건수 전부)·`groupBy`(담당자·협력사)·`verify`(정합성 6항목).
  - 엑셀 `buildWorkbook(res, XLSX)` — 「구매절감 실적」 열 19개 순서 고정, 차이금액·Impact·실적은 **수식**(`IF` 로 공란 처리, Impact 는 「환율」 시트 `VLOOKUP` + `ROUND`), 캐시값 함께 저장, 숫자 서식, 자동 필터. 「집계 및 검증」·「제외(비ZNB)」·「오류 내역」·「환율」·「안내」. XLSX 를 밖에서 받아 node 테스트에서도 같은 코드로 검사한다.
  - 예제 `sample()` 48행(가짜) — ZNB 외 3, 담당자 미매칭 2(선행 0 빠진 코드·표에 없는 코드), 예산단가 미매칭 2, 품목범주 1·조립비 공란, USD·EUR·CNY·JYP·JPY·GBP, 수량 공란, 「znb 」, 구매단가 열과 자재비가 다른 행, 예산 단가 중복 줄. `tools/make-samples.js` 로 `samples/` 세 파일 생성.
- 화면 `budget.html` · `js/budget-app.js`: 파일마다 시트 구성·열 목록·건수·첫 세 줄 미리 보기, 시트 종류 고르기, 항목 ↔ 열 짝짓기 표(필수 미매칭은 빨간 표시, 고를 때까지 계산 제외), 환율표 편집(localStorage), 집계 카드, 정합성 검증, 입력 경고, 담당자별·협력사별 표, 구매오더별 상세(값 출처 표시, 예산단가 미매칭 행에 입력 칸 → 바로 계산·localStorage 품번별 보관), 화면 입력 목록, 제외·오류 내역, 엑셀 내보내기, 계산 기준 설명(차이금액 부호 정의 명기). `#example` 로 오면 예제가 바로 돈다.
- index.html 상단 메뉴 「예산단가 방식」 + 안내 상자(`#go-budget-sample`), guide.html 「5. 예산단가 방식(v1.1)」 절, README·CLAUDE.md(§0·§1·§2 v1.1 표 1~11절·§3·§4·§5·부록 B), 기획서 v1.1.
